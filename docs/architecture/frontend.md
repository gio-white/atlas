# Frontend

Stack, hosting, routing, API client, and tooling for the React SPA in `web/`. Each page's
behaviour is in its feature doc under [domain/](../domain/); the route table is
[navigation](../product/navigation.md); tokens and theme are the
[design system](../product/design-system.md).

## Stack and hosting

The UI is a React SPA in `web/` (Vite, TypeScript, Tailwind, shadcn-style primitives). It is the only frontend. It consumes the HTTP API only. FastAPI does not render HTML templates. When `web/dist` is present, a GET that no API route matches returns `index.html` (or the static file at that path); a 404 that an API route itself returns, such as an unknown id, is passed through as JSON. `/journal`, `/side-quests`, and `/side-quests/{id}` are both SPA pages and GET API routes, so a document navigation to those paths (`Sec-Fetch-Dest: document` or `Accept: text/html`) gets `index.html` while fetches still get JSON (`SPA_PATHS_SHADOWED_BY_API` in `src/atlas/api/spa.py`). `/journal` is still a page; `/side-quests` and `/side-quests/{id}` are now old addresses that the SPA redirects to `/quests/side-quests…`, and they stay in the list so that redirect is reached. No current page address is a GET API route: quest pages live under `/quests/…` (the API has no `/quests` prefix, and quest detail pages use `/quests/goals/:id` rather than the API's `/goals/{id}`), Stats under `/stats/…`, Settings under `/settings/…`, Library under `/library/…`, and Habits stays on `/habit` because `/habits` is the API's list.

## Scope

Implemented: night app shell (a rail of destinations, a bottom tab bar on narrow screens, section tabs, and a header with the As of date and Add; [navigation](../product/navigation.md#shell)), typed `fetch` client, Home dashboard, Week, Area, Habit, Catalog, Screen Time, Entertainment, the quest screens (Main quests, Ambition, the goal quest map, Side quests, Side quest, Inbox, and the task drawer; [quests](../domain/quests.md#screens)), and placeholder Today and Calendar pages that Q3 of the [quest plan](../plans/quests-plan.md) replaces. The SPA does not recompute streaks, score, heatmaps, sleep consistency, library counts, or quest progress, eligibility, chapter state, or next action.

Routing: `web/src/App.tsx` writes every route with its full path, also inside a section, so each reads as the address it is and the docs drift test can match it against [navigation](../product/navigation.md). A section (`SectionLayout`) is a pathless layout route that renders the destination title, its tabs, and the page, and passes the shell context (`useShell`: the As of date, display name, Inbox count) on to it. `web/src/lib/nav.ts` is the one list of destinations and tabs; `nav.test.ts` checks that each has a route. `Redirect` sends an old address to its new one, keeping ids and the query string.

Shared code worth knowing: `web/src/components/settings/` holds configuration panels that load their own data and take an optional `onChanged` (Screen Time and data sources), so they can move between pages unchanged; `web/src/components/sleep/` holds the Sleep page charts; `web/src/lib/freshness.ts` formats "Last updated …" from a record's `created_at`. `web/src/lib/api.ts` has no functions that write sleep nights or screen sessions ([decision 0004](../decisions/0004-device-data-is-display-only.md)). Its **Quests** section is the complete typed client for every quest and time-block endpoint (types `Ambition`, `QuestGoal`, `QuestMilestone`, `SideQuest`, `Chapter`, `QuestTask`, `TimeBlock`, and the view shapes; functions such as `createQuestTask`, `organizeTask`, `promoteTask`, `completeQuestGoal(id, override)`, `createTimeBlock`, `completeTimeBlock`, `getMainQuests`, `getGoalTree`, `getInbox`, `getTodayQuests`, `getQuestCalendar`). Goal and task names carry a `Quest` prefix (`QuestGoal`, `listQuestTasks`) so they never read as the removed shapes. Q2 and Q3 build on it without adding functions. The SPA never recomputes quest progress, eligibility, chapter state, or next action; it shows what the API returns.

## Tooling

Home, the Habits pages, and a few small pages (Journal, Health, Appearance) are in the main bundle. Every other page (the quest pages, Sleep, Screen time, the Library pages, All entries, Catalog, and Area) is a `React.lazy` route in `App.tsx`, so it loads in its own chunk on first visit; `Layout` and `SectionLayout` wrap the page outlet in `Suspense` with the `PageLoading` skeleton. The main bundle is about 360 kB.

Package manager is pnpm (`web/pnpm-lock.yaml`, `packageManager` in `web/package.json`). Biome is the only linter and formatter (`web/biome.json`). Never npm, yarn, ESLint, Prettier, or oxlint. Dev: `cd web && pnpm install && pnpm dev` on `:5173`; Vite proxies API prefixes to `127.0.0.1:8000`. Document navigations (`Accept: text/html` or `Sec-Fetch-Dest: document`) to paths under an API prefix (`/journal`, and the old addresses `/screen`, `/sleep`, `/entertainment`, `/side-quests`, which the SPA then redirects) still get the SPA; the proxy also forwards the quest API prefixes (`/ambitions`, `/goals`, `/milestones`, `/side-quests`, `/chapters`, `/tasks`, `/time-blocks`). If the API is down, the proxy returns JSON `{detail}` instead of an HTML 502, and review pages keep their chrome with that message. Prod: `cd web && pnpm build` then `atlas serve` serves API and `web/dist` together. Frontend gates: `pnpm lint`, `pnpm test`, `pnpm build`. Vitest runs in Node by default; a component test that renders React opts into the DOM with a `// @vitest-environment jsdom` comment at the top of its file (for example `web/src/pages/displayOnly.test.tsx`).
